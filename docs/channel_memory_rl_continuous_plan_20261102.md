# 从首帧持续更新的数百秒机制探测

用户已经明确实际场景为持续会话、开始一次 acquisition、其后每帧 prefix Pilot，并允许先检验统计收益、后处理实时优化。本计划不重新询问已有授权，也不改变最终四 SNR 成功门槛。

128 帧只有 13.1072 秒；相对 1200 秒相干时间，它主要验证动作、更新、窗口验收与回滚是否可执行。修复后实际 seed 100010 的四 SNR 已完成：5/10/15 dB 出现正 Reward 窗口与非零累计记忆、四 SNR 各执行 4 次 PPO 更新。其 Data BER 未确认改善；这两项事实需要分别报告。100011–100012 的预设 128 帧开发验证仍须完整归档，不按其 Data 均值改动作或 checkpoint。

下一项独立机制问题是：在同一参数和反馈规则下，从首帧运行到约 210 秒时，在线记忆能否持续跟踪漂移，还是仅制造早期短暂变化？这不是正式四 SNR 主比较。

- 配置、checkpoint、6 个离散动作、8 帧窗口、32 帧 PPO 间隔、半径与 Reward 规则全部沿用修复后 128 帧运行，显式 FFT 后端。
- 先固定一个新的 `offline_train` 环境 seed **100013**（compare 索引 50013），**10 dB、2048 帧**，总时长 **209.7152 秒**，物理帧龄 0–2047。10 dB 来自前阶段已确认的记忆机制范围；不从本轮 Data 逐候选排名挑动作或改变 SNR。
- 同轨迹只运行独立 `Frozen Offline NN` 与正式 RL，目的是隔离持续适配机制并控制研究成本。传统设置不变；若进入主矩阵仍需五方法同波形审计，不能把本探测写作已超过传统 baseline。
- 同样只在会话开始 acquisition 一次；每帧的在线状态和参数均真实连续传递，不先 burn-in 到晚期再重置记忆。记录所有窗口动作、Reward、PPO 更新与验收后累计范数。
- 评分预先固定为完整会话、每 512 帧四段、末 1/3 减首 1/3 的 Online 对独立 Frozen 改善。单 seed 仅报告描述值，不生成独立 seed 推断区间；不据此选择 checkpoint。
- 若只是 Reward 变好而 Data 不改善，先用 Pilot 窗口记账和已固定分段定位，不调整反馈系数去追逐 Data。若有持续机制线索，再登记新的多 seed、四 SNR 数百秒比较；本探测本身不能完成总目标。

输出目录固定为 `logs/channel_memory_rl_continuous_2048f_seed100013_10db_20261102`；同名 `_timing.json` 记录完整进程墙钟。`latency_ms=0` 是当前比较入口的历史占位字段，不能作为实时性能证据；本阶段只报告实际研究进程耗时，不声称满足 102.4 毫秒每帧。
