# 持续跟踪的 128 帧机制验证

用户已明确选择持续跟踪：先做 128 帧机制验证，再覆盖数百秒连续会话。
此前单帧重置实验未通过，不能作为跨帧成功证据；本阶段直接检验保留参数的作用。

固定现有 prefix A/B 256 终点，配置不变，不新增训练、不选择最优留出 checkpoint。
在线按帧使用 Adapt 更新、Reward 验收；接受后保留 17 参数 head 到下一帧，
拒绝则保留动作前参数。AdamW 矩状态仍每次更新重置，与既有实现一致。
每个独立信道 seed 重置为离线参数，整会话累计参数偏移限制为 0.05。
冻结模型始终使用同一 checkpoint、同一完整接收帧作为对照。

- seed 83001–83003，heldout_edge，四 SNR 0/5/10/15，每条 128 帧，共 1536 个上下文、3072 条 A/B 记录。
- 早期固定第 0–41 帧，后期固定第 86–127 帧，沿用预先已有的首尾三分之一统计。
- 128 帧为 13.1072 秒；这是跨帧学习机制检查，尚未覆盖数百秒漂移场景。
- 主统计为 seed 级 Online 相对 Frozen 的改善及后期减早期改善，报告配对 t 区间。
- 记录更新接受数、有害接受数、相对离线起点的累计偏移，区分半径饱和与无有效方向。
- 不以部分运行结果提前结束、变更学习率/半径或扩大 seed；不把本固定动作实验称为正式 RL。

这一步没有引入多帧联合梯度或窗口 Reward；它只改变“参数是否跨帧保留”。若没有
稳定收益，后续在训练分布上定位窗口聚合是否能降低方向噪声，再决定跨帧离线训练。
若得到正向证据，再单独冻结数百秒会话和正式窗口 RL 的计划，不能直接宣布主目标完成。

实现验证：56 项定向测试通过，11.78 秒；新增累计偏移日志不改变已有更新与验收算法。
