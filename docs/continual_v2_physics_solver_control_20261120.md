# 物理解码求解精度对照：隔离实现

本实现位于隔离工作树 `D:/Research/02_研究点二_神经均衡_solver-control`、分支 `continual-solver-control-20261120`。主工作树P9仍采用启动时源码；本修改不整合到运行中的实验，不读取P9中途性能来选择迭代数，不分配或运行新的研究seed。

## 依据与可检验问题

已完成的[确定性审查](continual_v2_solver_and_logit_audit_20261120.md)说明固定8次CG并不保证求得精确线性高斯松弛解。这个问题独立于P9结果；不能由数值误差直接推断真实BER损失，也不能将更多迭代预先称为更优接收机。

新对照允许在相同checkpoint、同步、合法状态、soft映射和tail规则下只改变物理CG迭代次数。`physics_solver_iterations`只适用于`known_adapt_real_physics`，每个覆盖分支复制原checkpoint模型和配置，避免多个候选共享缓存时互相修改。默认不提供覆盖时仍走原配置。

`physics_solver_diagnostics=true`显式启用逐帧诊断。保存实际迭代次数、右端L2范数及未截断估计上的相对正规方程残差；残差重新执行正规算子计算，不能以CG内部递推残差代替。该额外算子工作包含在接收步骤耗时内。诊断仅依赖实际合法解码输入，既不读取Data标签也不使用真实CIR或噪声。

开启诊断前后的解码logits逐位一致。新实现不改变旧`2*z/σ²`映射，不增加Data反馈，也不将高斯松弛输出称为精确BPSK LLR。保留原float32运算、固定迭代与分母下限，所以32/64次也须看实际残差，不能直接称为收敛保证。

## 保存及审计

逐帧流显式保存`physics_solver_iterations`、`physics_solver_relative_residual`、`physics_solver_rhs_norm`。完整审计和固定前缀检查均验证预登记开关、次数、字段完整性及有限非负范围；按原预登记窗口保留均值。旧schema3没有启用该诊断时仍可审计，不向历史记录补造诊断字段。

未来完整闭环比较中，每个候选自己的soft-tail和同步轨迹可能变化；其BER差是求解设置引发的整个接收策略效果。若需要单帧固定上下文的精确中介归因，应另设共享合法上下文诊断，不能使用真实Data tail。
