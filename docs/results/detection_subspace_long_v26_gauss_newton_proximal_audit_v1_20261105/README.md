# 第二十六轮：降低GN近端权重的固定表示审计

## 假设与控制

v25只读方向诊断发现GN实际步幅远小于信赖域，Data oracle的最优系数位移常接近半径`0.8`。本轮不重训、不换checkpoint，只将GN更新近端权重从`0.1`减至`0.01`；阻尼`0.01`、Adapt温度`2.0`、逐步半径`0.15`、总半径`0.8`、验证门控/锚点收缩/回退、四SNR、信道、Pilot、接收窗口和v25的A/B checkpoint完全不变。评估seed仍为v25开发集`121600/121601/121602`，本轮属于复用开发集的机制对照，不能当作独立泛化证据。固定清单见[`v26审计配置`](../../../../configs/audits/detection_subspace_long_v26_gauss_newton_proximal_audit_v1.json)。

0/5/10 dB平均步幅约增至原来的7倍，候选接受数上升；15 dB仍因Pilot梯度极弱而几乎不动。更大的更新没有形成跨seed、跨SNR一致的BER收益，并让B臂相对A的交互保持负值。明细与输入指纹见[`summary.json`](summary.json)和[`frame_metrics.jsonl.gz`](frame_metrics.jsonl.gz)。

## 结论与下一步

近端权重`0.1`确实过度压小了低/中SNR的GN步幅，但将其降低十倍仍不足以获得可归因、可重复的在线增益。这一结果支持继续检查“更新尺度与离线表示/外循环是否匹配”，不能通过本轮复用开发seed声称有效。下一步固定prox=`0.01`、GN、验证保护和所有信道资源，做匹配的A/B离线训练（普通监督对照 vs GN内循环元训练），使用预先固定的新开发seed；只有重新训练后出现B相对A/Frozen的稳定收益才继续扩展。正式确认仍不启动。
