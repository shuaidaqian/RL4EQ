## 判断

1. **0 dB 的 H3 斜率不是数据后验/相位能修复的**：所有变体的斜率仍为负；最好的是 oracle `−0.0109`、EM2 `−0.0110`、block_phase `−0.0135`（soft 为 `−0.0152`）。
2. **0 dB 的窗口形状是“早期高 → 第三窗负 → 第四窗正”**，不是增长。0 dB 的 CIR 收敛快，增益在早期最大；后段受残余噪声/数据错误影响而波动。**0 dB 应表述为“早期收敛/后段饱和且晚窗为正”，不是“随帧增长”**；5/10/15 dB 才是增长。
3. **EM2 的 0 dB 改善跨 seed 异质**：`+0.0395 / +0.0090`；140002 上 EM2 还低于 soft。不能作为稳定机制。
4. **block_phase 是 0 dB 最一致的小改善**：两 seed 同向 `+0.0151 / +0.0254`；5/10 dB 接近 soft（5 dB `−0.00036`、10 dB `−0.00008` 相对 soft）；成本约 1.7 s/帧。
5. **5/10 dB 的 soft 仍最好**；EM2/EM3 略差；15 dB 两个 seed 的 Bayes 都略差于 Frozen，与 10×128 相反，属于 session 噪声。
6. **误差 lag-1 约 0**：0 dB 错误不显著自相关；EM 的收益主要来自“更新 CIR 后重解码”，不是误差相关模型。
7. **成本**：soft/block ≈1.7 s/帧、EM2 ≈2.1 s、EM3 ≈2.8 s、EM+block ≈2.1 s；102.4 ms 帧预算下均不实时。
