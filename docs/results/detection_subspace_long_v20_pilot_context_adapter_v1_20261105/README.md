# 第二十轮：Pilot更新上下文条件化逐位置Adapter

## 机制与协议

第十九轮的127符号空洞残差基在12维不可辨识，4维在线结果不稳定。本轮回到紧凑的低维上下文：2维在线状态`z`只由Adapt Pilot梯度更新；离线训练的非线性映射将`z`与每个已接收符号位置的7维接收特征结合，生成逐位置logit修正。`z=0`严格保留来源冻结网络。验证Pilot只守门，Data标签不进入在线更新、门控或回滚。信道、Pilot、接收窗口、数据划分、内循环设置、Frozen错误条件化外层目标和四臂预算保持不变。

清单见[`manifest.json`](manifest.json)。Pilot Jacobian审计在2维通过条件数门槛，最高合格维数为2；4维在个别SNR超过门槛，12维严重病态。检查结果见[`inspection.json`](inspection.json)。

## 开发结果

| SNR | B臂 Frozen BER | B臂 Online BER | Frozen−Online增益 | 配对95%区间 |
|---:|---:|---:|---:|---:|
| 0 dB | 0.17302789 | 0.17304145 | `−1.36e-5` | `[-7.19e-5, 4.48e-5]` |
| 5 dB | 0.03344727 | 0.03340658 | `+4.07e-5` | `[-6.04e-5, 1.42e-4]` |

| 15 dB | 0.00055610 | 0.00055610 | 0 | `[0, 0]` |

5 dB的点估计来自两个开发会话减少少量错误；0和10 dB各有一个会话增加误码。四点等权平均的在线改善约`+3.39e-6`，但区间均跨零，且A臂平均改善点估计相同；B−A交互在5 dB为正、10 dB为负，四点平均交互为0。因而该上下文Adapter带来了可观测的在线输出变化，但没有证明可归因、可重复的在线优势。B臂接受更新数为26/23/4/1（0/5/10/15 dB）；接受次数不是BER成功指标。增量更新约57–65 ms/帧，不含物理状态跟踪及端到端接收。

只读边界诊断见[`data_boundary_reachability.json`](data_boundary_reachability.json)：候选通常改善约49%–50%的当前错误边距、同时伤害相近比例的其他错误；三步局部移动上界内约2.8%/8.7%/28.6%/34.1%的错误逐符号可达。它解释了为什么软输出会变化而硬BER仍不稳定，不构成在线增益证据。

只读梯度诊断见[`update_alignment.json`](update_alignment.json)。Adapt与Data梯度余弦均值在0/5/10/15 dB约为`+0.208/-0.095/+0.125/+0.091`；5 dB当前单帧Adapt梯度余弦为`+0.139`，8帧历史均值却反为`-0.095`，平均历史梯度与当前梯度余弦约`0.269`。10/15 dB实际保留系数增量与Data下降方向余弦均值约`-0.70/-0.82`；15 dB当前Adapt梯度范数约`3.36e-6`。这些Data方向只作离线诊断，不作线上控制。该结果支持下一轮仅缩短梯度历史、观察更新是否更接近当前Pilot信息。

## 结论与下一步

该机制满足“更新的是神经上下文且逐位置读取已收到特征”的方法目标，也产生了非零候选变化，但没有稳定优于Frozen。诊断提示8帧平均会在5 dB把当前帧有利梯度方向反转，下一轮只将`inner_history_frames`从8改为1；不按SNR调度，其他结构、目标、数据和更新逻辑保持不变。若表现改善，再做匹配seed重复机制检验；若未改善，则进一步研究在线上下文更新映射。后续全新会话仍需保留独立确认。
