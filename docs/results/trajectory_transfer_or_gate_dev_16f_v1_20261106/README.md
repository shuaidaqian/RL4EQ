# 多帧轨迹训练门控代理 OR 单因素复核

本轮只改变离线多帧元训练的 Reward 门控平滑代理：从“平滑 BCE 与软错误同时改善”的保守 AND，改为近似线上规则“BER改善，或BER持平时BCE改善”的软 OR。在线前向仍逐帧执行未改动的 Reward 硬守门；Adapt Pilot 产生候选，Data 标签只进入离线外层目标与动作后事后评分。

A/B均从强离线 checkpoint `eme_bce_all_32_20260905_pilot256` 初始化，使用同一配置和8步预算。A只做 `BCE_all` 续训；B使用四帧持久参数轨迹及 OR 门控梯度代理。评估使用3个未参与训练的新会话、0/5/10/15 dB各16帧；Frozen 与 Online逐帧使用配对波形及相同物理状态跟踪。信道、Pilot、窗口、同步和状态分布均保持既有配置。

0/5 dB在线增益点估计仍无法与普通监督续训区分，交互区间跨零。0 dB后段收益减小，5 dB末窗和斜率区间跨零；10/15 dB没有有意义的检测增益。OR代理也未建立“传输帧越多、收益越大”的证据，不能进入正式确认。

## 解释与边界

本结果降低了“AND门控代理过度保守导致轨迹元训练失效”这一假设的可信度，但不能排除训练预算不足或软门控梯度质量问题。逐帧参数更新会被接受并持久化；此前审计显示0 dB部分会话累计位移到达0.05上限。故下一项应检验优化器的一阶/二阶状态是否也需要跨帧持久，以及硬拒绝时是否与参数一起原子回滚。它将改变在线更新状态机制，因此应先做无训练小规模机制验证，再决定是否值得重训表示。
